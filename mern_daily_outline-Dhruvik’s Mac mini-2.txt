	Prompting Techniques:
		
		Structured way of guiding LLM to:
			- Thikn better
			- Respond accurately
			- Follow logic
			- Reduce mistakes

		LLM - Probability Machine
		Prompt - Steering wheel


	Zero-Shot prompting
	-------------------
		Asking the model to perform a task without giving examples.

		Model relies on pre-trained knowledge
		No pattern guidance

		Usecase:
			- simple tasks
			- common knowledge tasks

		Limitation:
			- Inconsistent for complex tasks
			- May misinterpret intent

	Few-Shot Prompting
	------------------
		Provide examples in prompt to guide model behavior

		Model learns pattern from examples.

	 Usecase:
	 	- custom logic
	 	- Business rule
	 	- Domain specific tasks

	 Limitation:
	 	- Prompt becomes very long

	 Chain Of Thought (CoT)
	 ----------------------
	 Ask model to reason step-by-step

	 LLM performs better when reasoning is explicit.

	 	Usecase:
	 		- Math
	 		- Complex logic/reasoning

	 	Limitation:
	 		- Slower
	 		- More tokens


	 	Self-Consistency Prompting
	 	--------------------------
	 		Generate multiple reasoning paths --> Pick the best answer.

	 	How it works
	 		1. Ask model multiple times
	 		2. Get multiple answers
	 		3. Choose most common answer

	 		When to use?
	 			- When you need critical decisions
	 			- High accuracy needed

	 		Limitation:
	 			- Expensive (Multiple calls)
	 			- slower


	Tree of Thoughts (ToT)
		Model explores multiple reasoning paths like a tree

		How it works?
		Problem?
			Idea 1: --> Evaluate
			Idea 2: --> Evaluate
			Idea 3: --> Evaluate

			Choose best path.

			Ex:
				How to increase sales of a coffee shop?

					Think of multiple strategies and evaluate each before choosing the best.

		Be clear and specific

			Act as senior Nodejs architech, ....

		Break down the task
			Build a system

			Provide example

	 Provide context

		What is ? 
			A prototype is an object that another object can inherit properties and methods from.

			JavaScript uses prototype-based inheritance, not classical inheritance.

		Why?
			- To share methods between objects

		1. Look in obj
		2. Not found --> look in obj's prototype
		3. Continue up the chain
		4. Stop at null.

		obj--> obj.prototype--> null

	JavaScript searches properties through the prototype chain.


	Every function has property called prototype.

		This prototype is used only when function is called with new.

	Promise:
		A promise is a JavaScript object that represents the result of an asynchronous operation that will be available:
		- Now
		- Later
		- Or never

		
	- JavaScript is Single-Threaded (executes one task at a time)

	console.log("A"); // API Calls (fetch data)

	Promise object helps you to asynchronous operations.

	Promise manage asynchronous tasks without blocking JavaScript execution.

	Promise States
	-----------------------
		A promise object can be in only one of these three states

		1. Pending
			- Initial state
			- Operation has not finished yet
			- Neither success or failure

			Promise is just created

		2. Fulfilled
			- Operation completed successfully
			- Promise has a resolved value

			resolve("Data") --> Move state of the promise from pending to fulfulled

		3. Rejected
			- Operation failed
			- Promise has a reason (error

			reject("Something went wrong"); --> Pending to Rejected.


	Notes: Once promise is settle (fulfilled or rejected), its state cannot change.


	How do you create promise?

		let promise = new Promise(
			function(resolve, reject) {
				// async operations
			});

	GIT

	VCS - Versioning control system

		Tool that helps software developer team to manager changes to the source code over time.

			- Every modification made to the code
			- developers can go back to earlier versions of the code and compare changes

	Two types of VCS
		1. Centralized VCS	
			Single server where all versioned files as stored.

			Problem:
				- if central server fails --> all history made will be lost
				- Collaboration is limited when disconnected from the server

		Tool : SVN



		2. Decentralized VCS

			Every developer has local copy of entire repository, including history.
			Changes can be made locally and later pushed to the central repository when ready.

			Pros:
				- Every dev has full copy of project's history
				- Work can be continued offline
				- More robust against server failures.

			cons:
				- More disk space

		Tool: GIT


		Two types of storage:

		1. Snapshot based storage (Git)

			takes snapshot of entire project directory at time of each commit


		2. Delta based storage (C- VCS SVN)

			initial change --> delta1 --> delta2

			space efficient --> very slow down performance
