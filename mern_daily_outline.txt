	MongoDB Index:
	---------------

		An index is a special data structure that MongoDB creates to improve the speed of data retrieval.

		Instead of scanning every document in a collection, MongoDB uses an index to quickly locate the required documents.

		Without Index, MongoDB performs Collection Scan (COLLSCAN)

		With an index, MongoDB performs an index scan (IXSCAN)

		Improve ther performance of:
			- SELECT (find) operations
			- Sorting
			- Filtering
			- Joins using $lookup
			- Aggregation pipelines


Types of Index:
	1. Single Field Index

	2. Compound Index
		Multiple fields.

		customer_name and status

		db.customers.createIndex(
			{
				fullName:1,
				status:1
			}
		)

	3. Unique INdex
		Prevents duplicate values
		db.customers.createIndex({email:1}, {unique:true})
			when you insert
			{
				email:"john@gmail.com"
			}
		produce error : Duplicate Key Error

	4. Text Index
		Used for full-text searching

		Suppose we want to search customer names:

			db.customers.createIndex({fullName: "text"})

		db.customers.find(
			{
			$text:
			 {
			 	search : "John"
			 }
			}
		)

		Useful for:
			- Articles
			- Blogs
			- Product Description
			- Search Engines

		etc

	5. Multikey index
		Automatically created when indexing an array.

		{
		customerId: 101,

		skills: [

			"java", "mongodb", "Node"
		]
		}

		db.customers.createIndex({skills:1})

	6. TTL (Time-To-Live Index)

		Automatically deletes expired documents.

		Useful for:
			- Session Data
			- OTP
			- Cache
			- Temporary Data


		db.sessions.createIndex(
			{
			createdDate:1
			},
			{
				expireAfterSeconds: 3600
			}
		)

		Documents are automatically removed after one hour.


	db.customers.dropIndex

Best Practices:
	- Create indexes on fields that are frequently used in find() queries.
	- create indexes on fields used in sorting(sort())
	- crate index fields frequently used in $lookup operations
	- Prefer compound index when multiple fields are frequently queried together.
	- Use Unique index to prevent duplicate business data
	- Avoid create indexes on every field, Every additional index consumes storage an increases maintainance overhead.

	- Remember - index speed up read operations but slightly slow down insert, update, delete operations because mongodb must maintain indexes
	wheere data changes.
	- Remove unused indexes to reduce storage usage and improve write performance.

Data modelling in MongoDB
----------------------
	Process of organizing and structuring data inside MongoDB collections

	Two approaches:
		1. Embedding

			Related data stored inside same document.


			Adv:
				- One database read
				- Faster performance
				- No joins required
				- Simpler application code


			Used when:
				- child data always accessed with parent
				- child data is small
				- child data rarely changes independently

		2. Referencing

			Data is stored in separate collections.


			Adv:
				- No document size issue
				- Better scalability
				- Independent updates
				- Suitable for large datasets

			Used when:
				- Child data grows continiously
				- Child data is shared
				- Child data is accessed separately




Good MongoDB data model design should:
	- Reducing unnecessary queries
	- Avoid excessive data duplication
	- Improve read performance
	- Support future application growth (scalable)
	- keep documents within MongoDB's 16 MB document size limit

			- the result of one query depends on another query
			- we need dynamic filtering instead of hardcoaded values
			- we want to simplify complex sql statement
			- you may have intermediate calculations before executing main query


			Types:
				- Scalaer subquery -  returns exactly one row and one column
				- Row subquery - one row containing multiple columns
				- Table subquery	- returns multile rows and multiple columns - behaves like a temp table
				- correlated subquery 
						executes once for every row processed by the outer query.

				- non-correlated subquery  
						executes only once
						the result passed to the outer query

	Prototype:
		What is ? 
			A prototype is an object that another object can inherit properties and methods from.

			JavaScript uses prototype-based inheritance, not classical inheritance.

		Why?
			- To share methods between objects
			- To save memory

		Objects donot copy methods - they delegate to their prototype.

		Every js object --> hidden internal reference
			[[prototype]]

	JavaScript does:
		1. Look in obj
		2. Not found --> look in obj's prototype
		3. Continue up the chain
		4. Stop at null.

		obj--> obj.prototype--> null

	JavaScript searches properties through the prototype chain.


	Every function has property called prototype.

		This prototype is used only when function is called with new.

	Person.prototype = {
		constructor: Person;
	}




	let person1 = new Person("Alice");
	person1.greet(); // Output: Hello, my name is Alice

	Internally:
		1. New object created
		2. person1.[[prototype]] = Person.prototype == Object.prototype
		3. this bound to person1
		4. Object returned.

	constructor function links objects to their prototype automatically.


	person1.toString()

			- Initial state
			- Operation has not finished yet
			- Neither success or failure

			Promise is just created

		2. Fulfilled
			- Operation completed successfully
			- Promise has a resolved value

			resolve("Data") --> Move state of the promise from pending to fulfulled

		3. Rejected
			- Operation failed
			- Promise has a reason (error

			reject("Something went wrong"); --> Pending to Rejected.


	Notes: Once promise is settle (fulfilled or rejected), its state cannot change.


	How do you create promise?

		let promise = new Promise(
			function(resolve, reject) {

			});

	Basic Selector
		a. Universal selector
			Selects ALL elements on the page.

			* {

			}

		b. Type/Element selector

			Selects all elemnts of specific HTML tag.
			p {

			}

			Selects multiple elements with the same class name.

			.className {

			}

			padding - space inside the frame 

			margine - space between frames on the wall.

		Selects all matching elements inside another element, at any depth level.

		}

			Selects only direct children, not deeper nested elements.

			parent > child {
				property: value;
			}

	GIT

	VCS - Versioning control system

		Tool that helps software developer team to manager changes to the source code over time.

			- Every modification made to the code
			- developers can go back to earlier versions of the code and compare changes

	Two types of VCS
		1. Centralized VCS	
			Single server where all versioned files as stored.

			Problem:
				- if central server fails --> all history made will be lost
				- Collaboration is limited when disconnected from the server

		Tool : SVN



		2. Decentralized VCS

			Every developer has local copy of entire repository, including history.
			Changes can be made locally and later pushed to the central repository when ready.

			Pros:
				- Every dev has full copy of project's history
				- Work can be continued offline
				- More robust against server failures.

			cons:
				- More disk space

		Tool: GIT


		Two types of storage:

		1. Snapshot based storage (Git)

			takes snapshot of entire project directory at time of each commit


		2. Delta based storage (C- VCS SVN)

			initial change --> delta1 --> delta2

			space efficient --> very slow down performance
